# One rpm-ostree operand per line, and what each validator must say about it.
#
#   <kind> <ok|refuse> <operand>
#
# The daemon validates these operands in crates/sysknife-daemon/src/executor.rs and
# crates/sysknife-daemon/src/actions/validate.rs, and the root-owned helper
# packaging/sysknife-action-steps validates them again, because the helper is reachable
# through sudo without the daemon. Two copies of a rule drift, so both read THIS file and
# must give the same answer for every line:
#
#   * the Rust unit test `rpm_ostree_parity_corpus_agrees_with_the_daemon_validators`
#   * tests/release/action-steps.test.sh, class RpmOstreeVerb
#
# Kinds map to validators:
#
#   package  validated_install_package      (every layering action; helper rpm_package)
#   ref      validated_rebase_ref           (RebaseSystem; helper rebase_ref)
#   append   validated_safe_kernel_arg      (SetKernelArguments add; helper karg_append)
#   delete   validated_safe_kernel_arg_removal (SetKernelArguments remove; helper karg_delete)
#
# The helper's append screen is grub-kargs-edit's, which also refuses every downgrade in
# WEAKENING_KARGS (debugfs=on, iommu=off, init_on_alloc=0, ...). The daemon's add screen
# refuses only the ones in its own lists, so the others are left out of this file: the helper
# refuses them and the daemon would hand them on. tests/release/action-steps.test.sh pins the
# helper's lists to grub-kargs-edit.
#
# The operand is everything after the second space, so it may contain spaces. Lines that
# start with `#` and blank lines are skipped. Any other line that does not parse fails the
# test, so a typo cannot silently drop a case.
